The problem

Agents act blind. Reviewers trust logs. Nobody sees what happened.

01

Raw video blows the context window

A 60-second session at 30 fps is 1,800 frames. Feed that to a multimodal model and you pay for 1,790 near-identical images.

02

DIY ffmpeg scripts break in CI

Race conditions on Xvfb startup, corrupted MP4s from SIGKILL, missing moov atoms, 40 MB GIFs nobody can open in a PR.

03

Screenshots lack causality

A single PNG can’t tell you which click caused the regression. Without timestamped telemetry, visual evidence is just a guess.

Architecture

Five modules. One harness. From framebuffer to pull request.

Each layer is independently usable, fully typed, and battle-tested against headless Linux edge cases.

display.py

Virtual Display Manager

Owns the full Xvfb lifecycle. Configurable display number, resolution and DPI emulation, plus a readiness probe that blocks until X accepts connections.

  • display:99
  • resolution1920x1080x24
  • readinesssocket probe
recorder.py

Stream Recorder Daemon

Non-blocking ffmpeg -f x11grab in the background. Graceful SIGINT shutdown finalizes the moov atom — no corrupted containers, ever.

  • framerate15–30 fps
  • shutdownSIGINT · clean
  • telemetryJSONL events
processor.py

Post-Processing Engine

CRF-tuned H.264 / WebM for crisp code legibility. Two-pass palettegen → paletteuse GIFs small enough for GitHub. Optional click-ring overlays from telemetry.

  • codecH.264 · WebM
  • gif palette128/256 · bayer
  • overlayrings · crosshair
token_reducer.py

VLM Vision Pre-Processor

Keeps only frames that matter: scene-change detection plus exact frames at every logged action. Downsampled, deduplicated, labeled and timed for your LLM payload.

  • selectgt(scene,0.05)
  • anchorsaction timestamps
  • outputJPEG/WebP + JSON

Developer experience

Wrap your agent in four lines.

No daemons to babysit, no display variables to export, no ffmpeg flags to memorize. Enter the context, act, exit — artifacts are finalized automatically.

  • Instant screenshotstake_screenshot() returns bytes mid-run for in-loop agent reasoning.
  • Action telemetrylog_action() timestamps every click, key and scroll for overlays and keyframe anchors.
  • One export callMP4, GIF and VLM frame directory with a typed Artifacts result.
from agent_visual_harness import VisualHarness

# Usage in agent script:
with VisualHarness(display=":99", resolution=(1920, 1080), record=True) as harness:
    # 1. Agent runs GUI actions or Playwright tests here...
    harness.log_action("click", x=500, y=300)

    # 2. Grab instant viewport screenshot during execution
    screenshot_bytes = harness.take_screenshot()

# Upon exit, files are finalized automatically:
artifacts = harness.export(
    video_path="output/repro.mp4",
    gif_path="output/demo.gif",
    vlm_keyframes_dir="output/vlm_frames/"
)
print(f"Generated {len(artifacts.keyframes)} frames for VLM context.")
# Start a display + recorder, run any command inside it
$ dynamo record --display :99 --resolution 1920x1080x24 --fps 24 \
    -- python run_agent.py

# Compile artifacts from a finished session
$ dynamo export ./session \
    --mp4 output/repro.mp4 --crf 23 \
    --gif output/demo.gif --max-colors 128 --dither bayer \
    --overlay-clicks

# Produce a token-budgeted keyframe set for your VLM
$ dynamo keyframes ./session --scene 0.05 --max-size 1280 \
    --format webp --out output/vlm_frames/

FAQ

Questions engineers ask first.

What does Dynamo need on the host?

A Linux environment with Xvfb and ffmpeg installed, and Python 3.10+. It's designed for Docker, Kubernetes pods, CI runners, and computer-use sandboxes — no physical display or GPU required.

Does it work with Playwright, Selenium or computer-use agents?

Yes. Anything that renders to an X11 display can be recorded. Launch your browser or GUI inside the VisualHarness context and Dynamo captures it; call log_action() from your agent loop to anchor telemetry.

How does the token reducer decide which frames to keep?

It combines FFmpeg scene detection (e.g. select='gt(scene,0.05)') or image-difference scoring with exact frames at each logged action timestamp, then deduplicates and downsamples to your max bounding box.

What happens if my agent crashes mid-recording?

The context manager sends SIGINT to the recorder on exit — including on exceptions — so FFmpeg finalizes the moov atom and the MP4 stays playable.

Is any data sent to Dynamo's servers?

No. Dynamo is a local Python package. All recordings, frames and telemetry are written to paths you specify.
